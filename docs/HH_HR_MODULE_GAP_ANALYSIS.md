# Сверка HR-ТЗ SimpleHR с модулем «Кабинет HR»

Дата: 30.07.2026 (обновлено после первого прохода исправлений)

## Вывод

HR-ТЗ подтверждает базовую задумку модуля: нужен не просто просмотр hh.ru, а внутренний ATS-контур полного цикла — вакансии, кандидаты, воронка, интервью, история, отчёты и кадровый резерв.

`HH_HR_MODULE_TZ.md` глубже описывает интеграцию с HeadHunter: OAuth, webhooks, лимиты, платные просмотры контактов, справочники, безопасность. HR-ТЗ шире по бизнес-процессу: заявки руководителей, источники подбора, шаблоны писем, уведомления, кадровый резерв, адаптация после выхода.

## Совпадает

- Ведение вакансий и кандидатов.
- Автоматическое получение откликов (для hh.ru; по FarPost — импорт, см. ниже).
- Собственная воронка подбора.
- Карточка кандидата как единый профиль.
- Интервью, комментарии и история действий.
- Отчёты и аналитика по найму.
- Разграничение прав и журнал действий.
- HeadHunter как ключевая интеграция.

## Нужно добавить к нашему плану

- Заявка на подбор от руководителя подразделения до публикации вакансии.
- Согласование кандидата с руководителем подразделения как отдельный этап процесса (сейчас есть этап `submitted_to_manager`, но без маршрута согласования).
- Кадровый резерв: статус есть, нужен поиск по резерву и причины отказа справочником.
- Шаблоны автоматических писем: приглашение, напоминание, благодарность, отказ, оффер, выход на работу.
- Уведомления Telegram, Email, WhatsApp.
- Outlook/календарная интеграция для интервью.
- Отчёты в Excel, PDF и PowerPoint.
- Требования 152-ФЗ как отдельный набор acceptance-критериев: хранение, шифрование, доступ к ПДн, сроки ретенции.
- Будущий блок адаптации: наставник, чек-лист, welcome-курс, контроль испытательного срока.

## FarPost: решение изменено

Прежняя формулировка «FarPost — только после получения официального API, парсер не закладывать в основной контур» **отменена**. Публичного HR API у FarPost нет и не ожидается (см. `FARPOST_API_RESEARCH.md`), поэтому канал импорта через браузерное расширение признан рабочим и основным для этой площадки.

Ограничение, которое нужно зафиксировать в договорённостях с заказчиком: по FarPost **не будет** ни автоимпорта откликов каждые 5 минут, ни публикации «одной кнопкой сразу везде». Эти два требования HR-ТЗ выполнимы только для hh.ru.

## Что уже реализовано в коде

- Изолированный модуль `/api/hh/*` и UI `/hr/*`, роли доступа для HR, руководства и администратора.
- Локальные таблицы вакансий, кандидатов и событий кандидата (8 сущностей, миграция `1785260000000-CreateHhModuleFoundation`).
- Ручное создание вакансии и кандидата без подключённого hh.ru.
- Воронка из 8 этапов: новый отклик, скрининг, телефонное интервью, у руководителя, интервью с заказчиком, оффер, принят, отказ.
- История событий кандидата: создание, смена этапа, смена статуса, комментарий, интервью, импорт.
- Кадровый резерв как статус кандидата.
- Dashboard-метрики: открытые вакансии, новые отклики, кандидаты в работе, интервью на неделе.
- Импорт резюме FarPost: эндпоинт, парсер, панель импорта, Chrome-расширение.
- Экран интервью `/hr/interviews`: недельная сетка и список, deep link в карточку кандидата.
- Хранение настроек интеграции hh.ru с шифрованием секретов (AES-256-GCM), приёмник вебхуков, `GET /health/hh`.

## Исправлено 30.07.2026

- `GET /health/hh` закрыт JWT и ролью `admin` — раньше публично отдавал конфигурацию интеграции и телеметрию.
- Роли `director`, `general_director`, `financer` больше не получают ПДн кандидатов: сервер обезличивает ФИО, скрывает контакты, фото, возраст, ключ резюме, свободные тексты резюме и комментарии событий. По умолчанию (зритель не передан) ПДн скрыты.
- Повторный импорт с FarPost больше не затирает ранее собранные контакты пустыми значениями (режим merge).
- Парсер телефона: приоритет у значения рядом с меткой, нормализация к `+7`, отбраковка номеров резюме, годов и идентификаторов. Парсер зарплаты: отбраковка сумм вне диапазона 3 000 – 3 000 000.
- Приёмник вебхуков: свой rate-limiter, `insert` вместо `save` с корректным `409 Conflict` на дубликат при гонке, работает до завершения OAuth.
- Валидация больше не пишет тело запроса (ФИО, телефон, email, текст резюме) в лог.
- Списки вакансий и кандидатов пагинированы (50 на страницу, максимум 200); счётчики кандидатов считаются в БД вместо выгрузки всех связей.
- `HH_CRYPTO_KEY` проверяется при старте в production, а не при первом обращении.
- `email` кандидата валидируется как email.
- Появились тесты модуля (`hh-recruiting.service.spec.ts`): 15 проверок на обезличивание и парсер.

## Рекомендуемый порядок дальнейшей разработки

1. Заявки на подбор от руководителей и перевод заявки в вакансию.
2. Шаблоны писем и уведомления (email → Telegram → WhatsApp).
3. Шифрование контактов кандидатов и ретенция ПДн.
4. OAuth hh.ru, справочники, синхронизация вакансий.
5. Webhooks/отклики hh.ru и безопасное открытие контактов.
6. Аналитика и экспорт отчётов (Excel → PDF → PowerPoint).
7. Адаптация после приёма — отдельным будущим модулем.
