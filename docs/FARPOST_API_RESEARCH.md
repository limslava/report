# FarPost: исследование доступа и принятое решение

Дата проверки: 30.07.2026.
Статус: **решение принято, канал импорта через браузерное расширение — рабочий и основной для FarPost.**

## 1. Вывод

Публичного API FarPost для HR-контура работодателя **нет**. Это не «пока не нашли» — это установленный факт по всем доступным публичным источникам:

- официальный раздел FarPost `API` описывает только онлайн-обновление товарных прайс-листов через `https://www.farpost.ru/good/packet/api/sync`;
- раздел `Многопользовательский кабинет для работодателей` описывает работу с вакансиями, откликами и сообщениями **через личный кабинет**, а не через внешний API;
- вакансии доступны через публичный веб-раздел, но это веб-интерфейс, а не REST API/SDK;
- публикация вакансии выполняется только в личном кабинете на сайте;
- `robots.txt` закрывает `/personal`, `/job_response/*`, `*/resume/*`, `*/api/*`, `*ajax=1` — закрытый веб-контур для откликов и кабинета;
- публичные JS-бандлы содержат внутренние веб-ручки (`/ajae?ajax=1`, `/mmy.txt`, `/set/city/%GEO%?ajax=1`), но не документированный REST API вакансий/откликов.

**Следствие для проекта:** ждать API нельзя, потому что ждать нечего. Работа с FarPost строится на импорте, инициированном рекрутером.

## 2. Как это делают зрелые ATS

Ни Talantix, ни E-Staff не имеют открытого FarPost HR API и решают задачу так же:

- **Talantix** описывает FarPost как загрузку резюме через кнопку импорта. Автоматическая синхронизация вакансий и откликов заявлена отдельно и только для hh.ru.
- **E-Staff** использует ту же модель: расширение/кнопка забирает фрагмент веб-страницы с резюме и отправляет его в E-Staff. Плюс импорт из почты и документов. Официальный API у E-Staff есть, но это API самого E-Staff, а не FarPost.

То есть browser-extension import — это не костыль, а отраслевая норма для площадок без API.

## 3. Принятое решение

**FarPost подключается через расширение «Report FarPost Import» + серверный парсер. Это признанный рабочий канал модуля, а не эксперимент.**

Реализовано:

- эндпоинт `POST /api/hh/import/farpost/resume` (роли `admin`, `head_hr`, `hr_recruiter`);
- серверный парсер `parseFarpostResume()` в `backend/src/services/hh-recruiting.service.ts`;
- панель импорта на `/hr/candidates` с мастером «найти → установить расширение → сохранить»;
- Chrome-расширение MV3 в `browser-extensions/farpost-report-import`;
- кандидат создаётся с `source = 'farpost'`, ключ дедупликации `hh_resume_id = farpost:<id>`, событие `imported` в истории;
- поиск похожих дублей по ключу резюме, email, телефону и ФИО — результат показывается рекрутеру.

### Что канал даёт

ФИО (если открыто), должность, город, опыт, образование, навыки, желаемую зарплату, контакты (если рекрутер законно открыл их в своём кабинете FarPost), URL источника и дату импорта.

### Что канал принципиально не даёт — и об этом надо говорить заказчику прямо

- **автоматического импорта откликов каждые 5 минут по FarPost не будет.** Требование HR-ТЗ «каждые 5 минут получать новые отклики» выполнимо только для hh.ru;
- **публикации вакансии «одной кнопкой сразу везде» по FarPost не будет.** Публикация остаётся в кабинете FarPost; в Report фиксируется факт и ссылка;
- импорт всегда инициирует человек — расширением, файлом или вручную.

## 4. Требования к каналу для продакшена

Текущая реализация — MVP. До боевого запуска обязательно:

1. **Короткоживущий import-token вместо JWT пользователя.** Сейчас расширение хранит полноценный токен Report в `chrome.storage.local`. Нужен отдельный токен с узкой областью (только импорт), сроком жизни и возможностью отзыва из интерфейса Report.
2. **Боевые адреса** в `manifest.json` вместо `http://localhost:3101`; список origin синхронизировать с `FARPOST_IMPORT_ALLOWED_ORIGINS`.
3. **Правовое основание обработки.** Источник (`sourceUrl`), дата импорта и оператор импорта фиксируются в аудите — это уже сделано (`hr.candidate.import.farpost`). Дополнительно нужны: политика обработки ПДн с упоминанием импорта из внешних площадок, срок хранения и процедура удаления по запросу кандидата.
4. **Деградация парсера.** Парсер эвристический и завязан на вёрстку FarPost. Требования: не затирать ранее распознанные поля пустыми значениями (**сделано**, режим merge при повторном импорте); показывать рекрутеру, какие поля не распознаны; давать ручную правку карточки после импорта.
5. **Мониторинг качества.** Считать долю импортов, где не распознаны телефон/должность/опыт. Резкий рост — сигнал, что вёрстка площадки изменилась.
6. **Ограничение частоты.** Импорт инициирует человек, поэтому массового трафика к FarPost со стороны Report нет и не должно появиться. Автоматический обход страниц не закладывается.

## 5. Что остаётся за рамками

- **Скрейпинг личного кабинета** (cookie-сессии, внутренние `ajax`-ручки, автоматизация браузера) — не делаем: хрупко, тяжело в сопровождении и спорно по правилам площадки.
- **Автоматический обход публичных страниц вакансий** — не в основном контуре. Допустим только как read-only контроль витрины с лимитами и кэшем, отдельным решением.

## 6. Дополнительные каналы импорта (по мере необходимости)

- **Файл**: PDF/DOC/DOCX/HTML/EML — рекрутер скачал резюме или получил отклик на почту. Юридически и технически проще расширения.
- **Email**: разбор писем с откликами на выделенный ящик.
- **Ручной ввод**: уже работает.

Все каналы пишут одного и того же кандидата с полем `source`, поэтому воронка, отчётность и дедупликация не зависят от способа попадания в базу.

## 7. Архитектурная позиция

1. Внутренний HR-модуль единый для всех источников.
2. Provider-слой: `hh` — полноценная API-интеграция; `farpost` — канал импорта; далее при необходимости `avito` и др.
3. Для FarPost API-provider включается, только если площадка когда-нибудь даст официальный доступ. Отдельная задача, не блокирует работу.
4. В интерфейсе FarPost честно показывается как **источник импортированных кандидатов**, а не как синхронизируемая площадка.

## 8. Если понадобится вернуться к вопросу API

Запросить у менеджера/поддержки FarPost наличие официального API для работодателей и документацию по: авторизации; вакансиям (список, создание, публикация, продление, архив); откликам (список по вакансии, карточка, резюме, контакты); сообщениям; статусам и массовым операциям; webhooks или polling; лимитам, платным методам и требованиям по хранению контактов.
