# Система управления логистикой и отчетности

Веб-приложение для оперативного управления логистической компанией: ежедневная
отчетность по направлениям, планирование, графики работы персонала и техники,
учет топлива, справочники, бизнес-процессы (согласование договоров, проверка
кандидатов), склад временного хранения авто и модуль подбора персонала с
интеграцией hh.ru.

## 🎯 Назначение системы

Система выросла из ежедневной отчетности по пяти логистическим направлениям в
общекорпоративную платформу. Основные задачи:

- ежедневный учет оперативных данных и автоматический расчет плановых
  показателей (план на дату, % выполнения, план с переносом);
- формирование отчетов (Excel/PDF) и email-рассылка результатов;
- графики работы персонала и техники по подразделениям (план/факт,
  эффективность);
- учет расхода топлива по ТС и справочники водителей/техники;
- сквозные бизнес-процессы: согласование договоров, проверка кандидатов
  службой безопасности;
- склад временного хранения автомобилей (приемка, осмотр, фото, услуги,
  биллинг);
- подбор персонала: заявки на подбор, вакансии и кандидаты с интеграцией hh.ru.

**Направления деятельности (отчетность):**
1. Контейнерные перевозки – Владивосток (KTK VVO)
2. Контейнерные перевозки – Москва (KTK MOW)
3. ЖД перевозки (RAIL)
4. Автовозы (AUTO)
5. Дополнительные услуги (EXTRA)

## 🚀 Модули системы

### Показатели и отчетность (Planning v2)
- Excel-подобный ввод плановых и фактических значений по направлениям.
- Ежедневные отчеты с графиками выполнения плана, операционный отчет
  («план с переносом»), сводный отчет.
- Финансовый план с учетом ставок НДС по периодам.
- Экспорт в Excel; в Excel-дашбордах `Δ ДЗ/КЗ` и «Ср. стоимость заявки»
  рассчитываются в backend.
- Паспорт формул: см. `ARCHITECTURE.md` → «Паспорт формул (Planning v2)».

### SW Tech Dashboard
- Стартовая страница для ролей `admin`, `director`, `financer`, `head_sales`.
- Выбор периода (год/месяц), режим «итог месяца», динамика года
  План/Факт/Выполнение %, ключевые риски, drill-down в ежедневный и
  операционный отчеты.

### Графики работы (Operations Preview)
- Помесячные графики по подразделениям: Контейнеровозы, Автовозы, Диспетчера,
  Курьеры (Оперативники), Гараж (Автослесарь), СБ — раздельно Владивосток и
  Москва.
- Режим План/Факт с контролируемым копированием «План → Факт»; статусы смен
  (в т.ч. «Б — больничный», «Н — нет сотрудника», «С — снятие груза»);
  направления погрузки для автовозов (редактирование двойным кликом).
- Колонка «Прицеп» в контейнеровозах: сцепка водитель + машина + прицеп живет
  в строке графика; из контекстного меню строки копируется полная карточка
  водителя («Скопировать данные»).
- Подсказки ФИО/госномеров из справочников (только контейнеровозы/автовозы);
  админ может задать дату, после которой свободный ввод в графиках КТК
  отключается (новые значения — только из справочника).
- Эффективность (год) по контейнеровозам и автовозам; отчеты по графикам с
  многостраничным Excel-экспортом; отчет направлений автовозов.
- «ТС на линии (Факт)» в ежедневных отчетах КТК заполняется автоматически из
  факта графика контейнеровозов.

### Топливо
- Помесячный учет по каждому ТС (раздельно Владивосток/Москва): оператор
  вводит показание одометра, конечный остаток и заправку за месяц по ППР;
  пробег, начальный остаток, расход и л/100 км считаются автоматически
  (с возможностью ручной корректировки с маркером).
- Нормы расхода зима/лето на моделях ТС, настраиваемые границы сезонов,
  индикация отклонения от нормы.
- Состав месяца ручной: ТС добавляются из справочника техники, копируются
  из прошлого месяца, убираются через контекстное меню.
- Excel-экспорт за месяц и за год (формат исходной таблицы: 7 показателей ×
  12 месяцев + итог за год + блок норм).
- Доступ: админ + специалист по БДД и руководитель КТК своего региона.

### Справочники
- Водители (карточка с ПДн: паспорт, адрес, ВУ), Техника (госномер, модель,
  VIN, цвет, статус), Прицепы, Модели ТС с нормами расхода.
- Ведут руководитель/менеджер КТК своего региона, отдел кадров и админ;
  роли БДД доступа к ПДн не имеют; копирование карточки — по единому
  неизменному шаблону, копии логируются в аудит.
- Разовое наполнение из существующих графиков (админ), удаление — только
  админ из открытой карточки.

### Бизнес-процессы: согласование договоров
- Маршруты согласования с этапами и решениями участников (юрист, бухгалтерия,
  СБ, руководство), личный кабинет согласования (inbox), дашборд «мои
  согласования», история решений.
- SLA-правила по этапам с учетом производственного календаря.
- Обсуждения по договору со счетчиками непрочитанного, вложения с
  предпросмотром, лист согласования и печатный пакет (PDF).
- Справочники контрагентов и перевозчиков; поиск дубликатов договоров;
  доступ контрагентов через роль `counterparty_user`.

### Бизнес-процессы: проверка кандидатов (СБ)
- Заявки на проверку кандидатов с анкетами-вложениями.
- Предпросмотр вложений без скачивания: изображения, PDF, DOCX (конвертация
  в PDF через LibreOffice), HEIC → JPEG (heic-convert, с кешированием).

### Склад (временное хранение авто)
- Приемка и выдача автомобилей, осмотры с фотофиксацией (загрузка фото через
  tus — докачка при обрыве связи, резервное копирование).
- Клиенты склада, услуги и тарифы, выполненные услуги, биллинговые периоды.
- Роли: заведующий складом, кладовщик; страницы приемки/выдачи/операций.

### HR / подбор персонала (интеграция hh.ru)
- Заявки на подбор с маршрутом согласования, вакансии, кандидаты, интервью,
  отчеты рекрутинга, дашборд HR.
- Интеграция hh.ru: OAuth-подключение, синхронизация вакансий и откликов,
  вебхуки, ограничение частоты запросов, шифрование токенов
  (`HH_CRYPTO_KEY`), настраиваемый срок хранения ПДн.

### Календарь и заметки
- Календарь с заметками, адресаты и статусы прочтения, счетчик непрочитанного
  в реальном времени (WebSocket + fallback-опрос).

### Email-рассылки
- Расписания (ежедневно/еженедельно/ежемесячно), шаблоны, лог отправки.
- Типы рассылок: СВ (ежедневный), Planning v2 по сегменту, «СВ за месяц
  (итоговый)» (`monthly_final`).

### Администрирование
- Управление пользователями (приглашения, роли, сброс пароля, деактивация),
  журнал действий (аудит), системная статистика, настройки приложения
  (заголовок, дата отключения свободного ввода в графиках), SMTP, НДС.

## 🛠 Технологический стек

### Backend
- **Язык:** Node.js 18+ с TypeScript
- **Фреймворк:** Express.js
- **База данных:** PostgreSQL 15+ (прод: managed PostgreSQL 17 на Amvera)
- **ORM:** TypeORM (`synchronize` управляется `DB_SYNCHRONIZE`)
- **Кэширование/очереди:** Redis 7 + Bull
- **Реальное время:** WebSocket (`ws`) — счетчики непрочитанного
- **Файлы:** tus (докачиваемые загрузки фото склада), Excel — ExcelJS,
  PDF — pdfkit/pdf-lib, предпросмотр DOCX — LibreOffice, HEIC — heic-convert
- **Email:** Nodemailer (SMTP)
- **Аутентификация:** JWT

### Frontend
- **Фреймворк:** React 18 с TypeScript (Vite)
- **UI:** Material-UI (MUI) + кастомные Excel-подобные таблицы
- **State management:** Zustand
- **Графики:** Recharts, ECharts
- **Таблицы:** MUI X Data Grid, TanStack Table
- **Формы:** React Hook Form + Yup
- **HTTP клиент:** Axios; загрузка фото — tus-js-client

### Инфраструктура
- **Контейнеризация:** Docker + Docker Compose (локально)
- **Хостинг:** Amvera (прод `report`, стейдж `report-stage`, managed PostgreSQL)
- **Резервное копирование:** ежедневные бэкапы БД

## ⚙️ Установка и запуск

Подробная актуальная инструкция для разработки (включая запуск на локальной
копии продовой БД): **`docs/LOCAL_RUN.md`**.

Кратко:

### Предварительные требования
- Node.js 18+ и npm, Docker, Git
- Для предпросмотра DOCX: LibreOffice (`soffice` в PATH)

### Запуск
```bash
# 1. БД и Redis
cd backend
docker-compose up -d

# 2. Backend
cp .env.example .env   # отредактируйте при необходимости
npm install
npm run dev            # http://localhost:3001

# 3. Frontend
cd ../frontend
npm install
npm run dev            # http://localhost:5173
```

Администратор создается через переменные окружения
`DEFAULT_ADMIN_EMAIL` / `DEFAULT_ADMIN_PASSWORD`.

## 🛡️ Надежность

### Health-checks
- `GET /health` — жив ли процесс.
- `GET /health/db` — проверка доступности БД (`SELECT 1`, таймаут 2s, 2 попытки).
- `GET /health/db/metrics` — метрики доступности БД (latency + ошибки).
- `GET /health/redis` — проверка Redis; `NOT_REQUIRED`, если очередь отключена.
- `GET /health/scheduler` — статус планировщика email.

### Circuit breaker для БД
Если БД недоступна, API временно возвращает `503`. Настройки:
`DB_CIRCUIT_FAILURE_THRESHOLD` (по умолчанию `5`), `DB_CIRCUIT_OPEN_MS`
(по умолчанию `30000`).

## 🚢 Развертывание

- Деплой на Amvera: `amvera.yml` в корне; подробности — `AMVERA_DEPLOY.md` и
  `DEPLOY_WORKFLOW_AMVERA.md`.
- Прод (`main` → сервис `report`) и стейдж (`develop` → `report-stage`)
  собираются из соответствующих веток.
- Перед релизом — чеклист `backend/PRODUCTION_CHECKLIST.md`.
- Для очередей и рассылок необходим доступный Redis.
- Cache-заголовки фронтенда: `index.html` → `no-cache`, `/assets/*` →
  `immutable`.
- Резервное копирование: ежедневный `pg_dump` managed-БД + хранение вне
  платформы.
